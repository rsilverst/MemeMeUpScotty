Design choices baked in

  • Placement: below the canvas, above Save/Share. Reads as "what came before this" with the canvas as the focal anchor.
  • Capacity: unbounded for the live session. Every successful generation appends to the head of the carousel; older entries push to the right and remain reachable via horizontal scroll.
  • Order: most-recent on the left. Just-generated lands right where your thumb already is after pressing Energize. Older entries reachable by scrolling right; the right-edge fade gradient announces "more available".
  • Selected: 2dp Plasma500 border + faint outer glow. Unselected thumbs use the standard 1dp Space500.
  • Empty/single state: hide the strip entirely until there are 2+ generations. No reason to show a strip-of-one.
  • Loading state: strip stays visible (you can still browse history while a new gen is in flight). The freshly-generating attempt isn't added until it succeeds.
  • Tap behavior: tap a thumb → it becomes the active canvas image (reuses the existing setLoadedImage(file) path from PR 9). Captions persist; offset / size / style on each caption persist too (those live in MemeCanvas state and aren't tied to the image).
  • Persistence: in-memory only. App close clears the carousel; the existing MainActivity.onCreate cache sweep handles the on-disk side by deleting all generated_meme_* files at next launch.
  • File lifecycle during session: nothing is deleted while the app is alive — every generation keeps its cache file so any thumb is one tap away from being the active canvas. Footprint is bounded by how long the user keeps the session open; a typical session is small enough that this is fine for a personal tool.
